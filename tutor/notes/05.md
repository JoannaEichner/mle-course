## What the learner should own after this module

- An array is typed contiguous memory; operations run over whole arrays. Slices are views, mask and list indexing give copies.
- `axis` names the dimension that disappears. `keepdims=True` keeps it for broadcasting.
- Broadcasting aligns shapes from the right; `(n, 24) / (n,)` fails, `(24, 24) / (24,)` silently divides columns.
- Masks select, count (`sum`), give shares (`mean`) and combine with `& | ~` in parentheses. `np.where` picks elementwise.
- NaN propagates, is never equal to itself, is found with `np.isnan`, skipped with `nan*` functions. NaN is right when a value does not exist.
- Fixed-size integers wrap silently; floats compare with tolerance.
- MAE, RMSE, WAPE, bias: what each punishes. WAPE for model choice, bias alongside. MAPE breaks on zero days.

This is the first lab on FreshRetailNet. pandas comes in module 06; if the learner asks why not pandas, the answer is that pandas is built on these arrays and the lab shows what it does underneath.

## Tasks

### 05.6 `to_matrix`

- `np.argsort(ids)` alone: days within a series come out in arbitrary order. The check shuffles days. Ask what order two rows of the same series end up in.
- `np.lexsort((ids, days))`: sorts by day first. The last key is the primary one; the check's expected matrix shows the result.
- Checking only counts per series (`return_counts`): a series with a duplicated day and a missing day has the right count. The check has that case.
- A Python loop over series: correct, slower; mention K7, do not block.
- Modifying the input in place with `ids.sort()`: the check compares the input before and after.

### 05.1 `prepare`

- Checking NaN before masking: a NaN in a masked-out row raises when it should not. The docstring says "a kept value". The mutation test for NaN does not catch this direction; ask what the docstring says.
- Not flattening: a (n, 7) matrix and its forecast are valid input; the lab passes matrices.
- Returning Python lists: later metrics call `.mean()` on them.

### 05.2-05.3 metrics

- `np.mean(np.abs(a - p))` with lists works too, but after `prepare` both are arrays.
- WAPE as `np.mean(np.abs(a - p) / a)`: that is MAPE, with division by zero on zero days. The mutant "mean of row ratios" is this bug.
- Bias as `(a - p).sum() / a.sum()`: sign flipped. The docstring says positive means too high.
- Returning `np.float64` instead of `float`: works; the check may not care, mypy does (`-> float`). `float(...)` is the fix.

### 05.7 `seasonal_naive`

- `np.tile(last_season, (1, horizon // season))`: too short when `horizon` is not a multiple of `season`. The check uses horizon 4 with season 3.
- Validation of `history.shape[1] < season` missing: the check passes season 7 with 6 columns.

### 05.4 `row_shares`

- `matrix / matrix.sum(axis=1)`: shape error for non-square input. Point at the lecture's broadcasting table.
- Dividing and then replacing `inf`/NaN: works, but emits a RuntimeWarning; the `np.where` before dividing is cleaner.
- Zero rows turned into zeros: the check wants NaN. Ask what "each hour had a zero share" would claim about a day without sales.

### 05.5 tests

Same mechanism as 04.2. Data that distinguish mutants: equal-size errors make MAE equal to RMSE; rows of different scale separate WAPE from a mean of ratios; a masked-out row that would change the result tests the mask; NaN and shape mismatches are `pytest.raises(ValueError, match=...)`.

## The questions in 05.8

Discuss, do not grade.

1. **Lower WAPE on in-stock days.** On stockout days sales stop when the shelf is empty; the recorded number is below demand and below what the history suggests, so every forecast looks worse there. Masking scores the forecast against demand where it was observed.
2. **One week.** No: one week is one sample, with its own weather, holidays and promotions. Rankings need several test windows (module 11) and ideally a look per segment.
3. **`mean` versus `nanmean`.** Every column has NaN from the no-sales days, so `mean` returns NaN everywhere.
