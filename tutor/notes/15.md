# Module 15: object storage and SQL

Code: `src/freshcast/storage/` (`retry.py`, `s3.py`, `sql.py`), the `storage` section of `config.py`, the publishing step at the end of `pipeline.train`. Tests the learner writes: `tests/storage/test_s3.py`.

## What the learner should own after this module

- S3 stores objects under keys; "folders" are a naming habit. The same code talks to Amazon or a local server: only endpoint and credentials change, and they come from settings and the environment.
- Credentials never sit in code or committed config.
- Retry only what can pass by itself, a bounded number of times, with growing waits, re-raising the last error.
- Tests of network code run against a fake (moto), never the network, and never really sleep.
- SQL answers the same questions as pandas: `WHERE` is a mask, `GROUP BY` is `groupby().agg`, a window function with `PARTITION BY` is `groupby().transform/shift/rolling`.
- Values go into SQL as parameters (`?`), never pasted into the text.

## Local server

MinIO stopped publishing community images and binaries in 2025. The course uses the moto server: `uv run moto_server -p 9000` or `docker compose up -d`. It accepts any credentials, but boto3 and DuckDB still need a pair: `configs/s3.env.example`. It keeps data in memory: a restart empties the buckets. Say so before the learner is surprised.

DuckDB against a local endpoint needs `ENDPOINT 'localhost:9000'` (no scheme), `URL_STYLE 'path'`, `USE_SSL false`. `connect()` sets them from the settings. The first `INSTALL httpfs` downloads an extension: it needs internet once.

## Tasks

### 15.1 Storage settings

- Accepting any string as a bucket name. Ask what Amazon does with `My_Bucket`.
- Keeping slashes in the prefix, then building `models//run/...` keys. Ask them to print a key.

### 15.2 `retry` and `is_transient`

- Retrying every exception, including `AccessDenied` or a missing key. Ask: "Which of these errors would be different a second later?"
- Waiting after the last attempt, or swallowing the final error.
- `time.sleep` hard-wired, so tests take seconds. Point at the `sleep` parameter.
- Forgetting `functools.wraps`: the check looks at the name and docstring.

### 15.3 `S3Storage`

- `exists` implemented with `list_keys(key)`: true for a prefix such as `models`. The check and a mutant catch it.
- `exists` returning False on any error. Ask: "If the password is wrong, is the object missing?"
- Opening the file outside the retried function in `upload_file`: a retry sends a half-read handle.
- `list_keys` reading only the first page. Ask what happens with 1001 objects.

### 15.4 `fetch`

- Caching by key only, so a replaced object returns the stale copy. Lead to ETag.
- Accepting keys with `..`: a key from the bucket can then write outside the cache.

### 15.5 Publishing

- Uploading `metadata.json` first, so a half-uploaded model looks complete.
- Overwriting a published signature. Ask what the forecasts made with the old model point to afterwards.
- `fetch_model` downloading straight into the final directory: a failure leaves half a model where the next run finds it.

### 15.6 Tests

Seven mutants: prefix treated as key, unsorted listing, silent missing download, delete doing nothing, stale cache, no retry, retrying permanent errors. The last two need tests with a hand-made fake client (a small class with `head_object`), not moto. That idea is new to most learners: suggest it at rung 2.

### 15.7 and 15.8 SQL

- Formatting values into the SQL string with an f-string. It works on the sample; ask what happens with a value containing a quote.
- `store_summary` grouping by store and city: a store in two cities silently becomes two rows.
- An inner join that drops fact rows with unknown keys, the SQL twin of module 07's merge trap.
- Filtering a window function in the same `SELECT`'s `WHERE`: syntax error. Lead to a `WITH` step.
- `LAG` without `PARTITION BY`: the cross-series leak of module 07 again.
- `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`: includes today. The check compares with `add_rolling_mean`.
