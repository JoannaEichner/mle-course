# Module 04: tests and the package

Lecture: `lectures/04-testing/index.html`. Lab: `labs/04-testing/`. Code: `src/freshcast/models/local.py`, tests: `tests/models/test_local.py`. Checks run from the terminal or the notebook without a target: `check("04.1")`. Checkpoint 1 closes the module.

## What the learner should own after this module

- A test arranges small explicit data, acts once, asserts a concrete value computed by hand (T2).
- Errors are part of the contract: `pytest.raises` with `match` (T3). Floats: `pytest.approx`.
- `parametrize` multiplies; fixtures provide data or resources (`tmp_path`); `conftest.py` shares them.
- Tests do not depend on network, clock, unseeded randomness or order (T4). First choice: pass the dependency as an argument; then `monkeypatch`; `Mock` last.
- A passing test proves nothing until it fails on broken code: data must distinguish correct from incorrect behaviour.
- `src/` layout and editable install; `pyproject.toml` ranges versus `uv.lock` pins; `uv add / lock / sync / run`.
- Poetry does the same job with different defaults.

## Facts worth having at hand

- The 04.2 check needs at least 6 tests (parametrized cases count) that pass on the learner's own code, then runs them against 8 mutants of `local.py`:
  1. naive repeats the first value instead of the last,
  2. seasonal behaves like naive,
  3. seasonal is shifted by one step,
  4. moving average over the whole history instead of the window,
  5. `predict` returns one value too many,
  6. `fit([])` accepted,
  7. `predict(0)` returns `[]`,
  8. `predict` before `fit` returns zeros.
- The mutation run takes a few seconds per mutant.
- `uv run course catchup 04` fills in `local.py` bodies only for modules before 04, so it does not help with 04.1 itself; it rewrites `labs/02-functions/carparts.py` and `labs/03-classes/demand.py` with the reference (backups in `.course/backup/`).
- Poetry 2.5 (tested): `poetry new demand-poetry` creates a `src/` layout with `tests/` and a PEP 621 `[project]` table. `poetry add --group dev pytest` writes `"pytest (>=9.1.1,<10.0.0)"` under `[dependency-groups]`; uv writes `"pytest>=9.1.1"`. Poetry puts the environment in `~/.cache/pypoetry/virtualenvs/<name>-<hash>-py3.12`; uv in `.venv` inside the project. `uv init --package` also creates `.git`, `.python-version` and a script entry point. The build backend `uv init` picks depends on the uv version.
- On some installs `uvx` is not on the PATH; the lab uses `uv tool install poetry`, which always works.

## Tasks

### 04.1 Forecasters in the package

- Changing signatures or defaults (for example `season=12` from lab 03's notebook). The docstrings in the file are the contract; ask them to reread it.
- Returning ints: `NaiveForecaster().fit([3, 5, 4]).predict(3)` gives `[4, 4, 4]` if `fit` keeps the list as is. The check says floats are expected.
- `fit` keeping the caller's list: the check mutates the list afterwards.
- Import errors after editing: usually a missing import that `ruff check` reports as F821.

### 04.2 Tests

- Tests whose expected value comes from the code under test, for example comparing two calls of the same forecaster. They pass on every mutant. Ask: "Where did the expected value come from?"
- Data that cannot distinguish mutants: histories of equal values, a season equal to the horizon, a window equal to the history length. The check lists the survivors; ask what input would give a different answer for the mutant.
- `pytest.raises(ValueError)` without `match`. Passes the check. Mention T3; not blocking.
- Parametrizing over forecaster *instances* at module level (as the given pattern does) shares one instance between cases. Here harmless, since `fit` resets the state. If they ask, explain that a fresh instance per test is safer in general.
- Tests in the wrong file or with the wrong prefix: `pytest` does not find them, the check counts fewer than 6.
- Tests fail on their own code: the check says so before running mutants; send them to `uv run pytest tests/models -q`.

### 04.3 Poetry sandbox

No check. Good answers:

1. Poetry: a shared cache directory outside the project. uv: `.venv` in the project.
2. Poetry adds an upper bound below the next major version; uv only a lower bound. An upper bound blocks a new major release until someone raises it; no upper bound lets it in on the next lock refresh, tested or not.
3. `poetry.lock`, `uv.lock`; both belong in git for applications, so every install is identical.
4. `poetry new`, `uv add`, `poetry install`, `uv run`, `poetry lock`.
