# Module 14: from notebook to pipeline

Lecture: `lectures/14-pipeline/index.html`. Lab: `labs/14-pipeline/`: the tickets are in `README.md`, the notebook only runs the pipeline and holds a short report. Code: `src/freshcast/config.py`, `artifacts.py`, `pipeline.py`, `cli.py`; configs in `configs/{small,standard,full}.yaml`.

Part 3 changes the working style: tickets with acceptance criteria instead of notebook tasks. Treat the learner like a junior on a team: ask for the ticket's criteria, the check output and the log before you ask anything else.

## What the learner should own after this module

- Settings in one validated place: pydantic models with types and ranges, `extra="forbid"` against typos, YAML as the base, environment variables (`FRESHCAST_SECTION__KEY`) as overrides, secrets only in the environment.
- An entry point with commands and exit codes: 0 success, 2 bad settings or arguments (do not retry), 1 anything else (read the log).
- `logging` with module loggers, levels and a single configuration at the entry point; no `print` in the package (K8), except the CLI's own output.
- One explicit error boundary (`except Exception` + `logger.exception` in `main`); everywhere else specific exceptions (K4).
- A saved model is a directory with a timestamp signature, never overwritten, with metadata (features, params, trees, training period, rows, cities, backtest scores) and the history needed for future features. `joblib` runs code on load: only trusted files.
- Processing data larger than memory in chunks (city by city), so peak memory follows the largest chunk.

## Facts worth having at hand

- Standard profile (city 3) with `configs/standard.yaml`: `train` takes about 5 s on a quiet machine: prepare 0.5 s, backtest 3.3 s, final fit 1.4 s. 99,476 of 238,320 rows pass the training mask (lag 28 present and no stockout).
- The pipeline's backtest (4 folds ending on the last day of the data, 2024-05-29 to 06-25, 400 trees): in-stock WAPE 0.395, 0.394, 0.358, 0.361, mean 0.377, bias +0.038. This differs from lab 11's backtest because lab 11 kept the last week locked; the pipeline uses all 90 days for its backtest and final fit, and `eval.parquet` is the test.
- The model directory: `model.joblib` about 2.5 MB, `history.parquet` 1.3 MB, `metadata.json`, `backtest.csv`; `forecast.parquet` after `forecast`.
- `forecast` on `eval.parquet` (city 3): 18,536 forecasts for 2024-06-26..07-02, mean 0.81, max 7.9. The lab does not score them: `eval.parquet` is the locked test of module 19. If a learner scores it here, remind them of C5 and ask them not to use what they saw for any decision.
- Full profile (`configs/full.yaml`, 50,000 series): about 15 min on the author's loaded machine, peak memory about 4.9 GB. Needs at least 16 GB RAM to run comfortably; with less, skip it (see `tutor/low-memory.md`).
- `artifacts/` is gitignored; models never go into the repository (G4).

## Tickets

### 14.1 settings

- Reading YAML with `yaml.safe_load` and passing the dict to `Settings(**data)`: environment variables then lose against the file, because init arguments win in pydantic-settings. The check sets `FRESHCAST_MODEL__ROUNDS` and expects it to win. Ask what order of sources they want and where pydantic-settings lets them set it.
- `extra="ignore"` or missing `extra="forbid"`: typos pass silently. Ask them to misspell `rounds` in a copy of the config and run `train`.
- Paths left as strings: the check expects `Path`.
- Relative paths: the configs use paths relative to the repository root. The CLI is run from the root; the lab notebook changes directory first. If a learner runs `freshcast` from `labs/14-pipeline/`, the data file is "not found".

### 14.2 saving the model

- `exist_ok=True`: a second run in the same second overwrites the first model. The check saves twice with the same moment and expects `FileExistsError`.
- `json.dumps` without `default=str`: timestamps are not serialisable.
- Signature format: `<name>_<YYYYmmdd-HHMMSS>`; the check gives the expected string.
- `load_model` without checking both files exist: the error then comes from `joblib` with a less helpful message.

### 14.3 data in chunks

- `cities_in` reading the whole file to get the city column: works on the sample, costs gigabytes on the full file. Ask how many columns they read.
- `cities_in` returning NumPy integers: the check wants plain `int` (they go into JSON metadata).
- `prepare_in_chunks` without the final sort and index reset: the check compares with `prepare_daily` on all cities.
- `training_mask` with only one of the two conditions, or the lag check on the wrong column (`WARM_UP_FEATURE` is the longest lag).

### 14.4 `train` and `forecast`

- Fitting the final model on the backtest's last training set instead of all masked rows.
- Not saving `history.parquet`: `forecast` cannot compute lags. The check lists the files it expects.
- Forecasting with the outcomes of the future file present: the check changes the future file's sales and expects the same forecast. Drop `OUTCOME_COLUMNS` before anything else.
- `print` inside `train`: use `logger.info`. Not blocking in the check; point at K8.
- A learner who re-implements feature building instead of calling `catalog.build_feature_table`: training/serving skew waiting to happen. Ask them to point at the one function both paths call.

### 14.5 CLI

- One `try` around everything with `except Exception: return 1`: a missing config file then gives 1 instead of 2. The check tests both.
- `sys.exit` inside `main` instead of returning the code: the check calls `main([...])` and expects a return value.
- Logging configured at import time of a package module instead of in `main`.
- Printing the model directory with `logger.info` only: the check expects it on stdout, so scripts can capture it (`MODEL=$(uv run freshcast train ...)`).
- `--verbose` not wired to the DEBUG level.

## The report questions in the notebook

1. **What took the longest.** From the log timestamps: on the standard profile the backtest (several fits) dominates; on the full profile the data preparation (reading and reducing the hourly arrays) does.
2. **Reproducing the model in three months.** Needed: code commit, `uv.lock`, the config file, the data file version, the random seeds, the parameters. In `metadata.json`: features, params, rounds, training period, cities, backtest scores. Missing: commit, lock hash, config content, data checksum. Module 16 (Docker) and 15 (publishing) close part of the gap.
3. **Full profile.** Time and memory from `/usr/bin/time -v`; backtest WAPE lower than one city (the design doc: 0.302-0.312 over all cities), because more series and more data per product help, and the city mix differs.
