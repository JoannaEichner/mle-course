    Struktury danych i przepływ

    Umiesz napisać pętlę i funkcję. Ten moduł dotyczy tego, co dzieje się pod spodem, kiedy piszesz b = a. Od tej odpowiedzi zależy, czy funkcja czyszcząca dane zepsuje Ci oryginał.

    • Czas: około 60 minut
    • Wymagane: zmienne, pętle, funkcje, listy i słowniki
    • Potem: lab 01, około 6 godzin

    Po tym wykładzie będziesz umiał:

    • przewidzieć, kiedy zmiana jednej zmiennej zmienia też inną,
    • dobrać listę, krotkę, słownik albo zbiór do zadania,
    • pisać comprehensions i generatory zamiast pętli budujących listy,
    • czytać plik linia po linii i zamykać go zawsze, także przy błędzie,
    • zgłaszać i łapać wyjątki tak, żeby komunikat mówił, co jest nie tak.

    W każdym bloku poniżej najpierw wybierz, co Twoim zdaniem wypisze kod. Dopiero potem go uruchom. Python ładuje się do przeglądarki przy pierwszym uruchomieniu, co trwa kilka sekund i wymaga sieci.

    Nazwy i obiekty

    W Pythonie zmienna nie jest pudełkiem z wartością. Jest nazwą przyczepioną do obiektu. Przypisanie b = a nie kopiuje niczego. Przyczepia drugą nazwę do tego samego obiektu.

    prices = [10, 12, 15]
promo = prices
promo[0] = 8
print(prices)
    • [10, 12, 15]Tak by było, gdyby promo = prices robiło kopię. Nie robi.
    • [8, 12, 15]Tak. prices i promo to dwie nazwy jednej listy. Zmiana przez jedną jest widoczna przez drugą.
    • Błąd: nie można zmieniać promoListę można zmieniać przez każdą nazwę, która na nią wskazuje.

    Stąd biorą się dwa różne pytania o równość:

    • a == b pyta, czy obiekty mają taką samą wartość.
    • a is b pyta, czy to ten sam obiekt.
    a = [1, 2]
b = [1, 2]
c = a
print(a == b, a is b, a is c)
    • True True Truea i b powstały z dwóch osobnych literałów, więc to dwie różne listy o tej samej zawartości.
    • True False TrueTak. Ta sama wartość, dwa obiekty. c to druga nazwa listy a.
    • False False True== porównuje zawartość, a ta jest identyczna.
    Reguła

    is używaj tylko do porównań z None: if value is None. Wszędzie indziej chodzi Ci o wartość, czyli o ==.

    Mutowalność

    Obiekty dzielą się na te, które da się zmienić w miejscu, i te, których się nie da.

    MutowalneNiemutowalne
    list, dict, setint, float, str, tuple, frozenset

    Dopóki obiekt jest niemutowalny, współdzielenie go między nazwami jest nieszkodliwe: nikt nie może go zmienić pod Twoją nieobecność. Z listą i słownikiem jest inaczej. Najczęściej wychodzi to przy funkcjach, bo argument funkcji to kolejna nazwa tego samego obiektu.

    def add_promo(calendar, day):
    calendar.append(day)
    return calendar

week = ["pon", "wt"]
weekend = add_promo(week, "sob")
print(week)
    • ['pon', 'wt']Funkcja nie dostała kopii. calendar wewnątrz funkcji to ta sama lista co week na zewnątrz.
    • ['pon', 'wt', 'sob']Tak. append zmienił listę w miejscu, a week wciąż na nią wskazuje. Funkcja zmieniła dane wywołującego.
    • Błąd: week nie istnieje wewnątrz funkcjiFunkcja nie używa nazwy week. Dostaje obiekt pod nazwą calendar.

    Ta sama mechanika stoi za jedną z najsłynniejszych pułapek Pythona. Wartość domyślna argumentu powstaje raz, w chwili definiowania funkcji, a nie przy każdym wywołaniu.

    def collect(sale, basket=[]):
    basket.append(sale)
    return basket

collect(3)
print(collect(5))
    • [5]Tak by było, gdyby pusta lista powstawała przy każdym wywołaniu.
    • [3, 5]Tak. Oba wywołania dopisują do tej samej listy, która żyje razem z funkcją. Poprawny zapis to basket=None i utworzenie listy w środku.
    • Błąd: lista nie może być wartością domyślnąMoże. Python na to pozwala i dlatego to pułapka, a nie błąd składni.

    Kopia płytka i głęboka

    Skoro przypisanie nie kopiuje, kopię trzeba zrobić jawnie. list(x), x.copy() i x[:] robią kopię płytką: nowy kontener, w którym siedzą te same obiekty co w starym.

    stock = {"jabłka": [5, 3], "gruszki": [2, 2]}
snapshot = stock.copy()

stock["jabłka"].append(9)
stock["śliwki"] = [1]
print(snapshot)
    • {'jabłka': [5, 3], 'gruszki': [2, 2]}Tak działałaby kopia głęboka, copy.deepcopy(stock).
    • {'jabłka': [5, 3, 9], 'gruszki': [2, 2]}Tak. Nowy klucz nie trafił do kopii, bo słownik jest osobny. Lista pod kluczem jabłka jest jednak ta sama w obu słownikach.
    • {'jabłka': [5, 3, 9], 'gruszki': [2, 2], 'śliwki': [1]}To zawartość stock. snapshot jest osobnym słownikiem i nowych kluczy nie dostaje.
    Reguła

    Funkcja nie zmienia swoich argumentów. Zwraca nowy obiekt. Wyjątkiem jest funkcja, która w nazwie i w docstringu mówi wprost, że zmienia w miejscu.

    Ta reguła zostanie z Tobą do końca kursu. Wróci w module 06 jako "funkcja czyszcząca zwraca nową ramkę" i w każdym review.

    Cztery kolekcje

    Python ma cztery wbudowane kolekcje, których będziesz używać codziennie. Różnią się tym, czy pamiętają kolejność, czy pozwalają na powtórzenia i czy da się je zmienić.

    TypPrzykładKolejnośćZmiennyDo czego
    list[3, 5, 4]taktakciąg wartości: sprzedaż miesiąc po miesiącu
    tuple("T1", "1998-01")takniestały zestaw pól: nazwa i data startu serii
    dict{"T1": 12}tak (kolejność wstawiania)takwyszukiwanie po kluczu: statystyki po nazwie serii
    set{"T1", "T7"}nietakprzynależność i unikalność: które serie mają braki

    Różnica, którą czuć przy danych: sprawdzenie x in lista przegląda listę element po elemencie, a x in zbior i x in slownik trafia od razu. Dla 2 674 serii to bez znaczenia. Dla 4,5 miliona wierszy to minuty kontra ułamek sekundy.

    Klucz słownika i element zbioru muszą być niezmienne. Krotka może być kluczem, lista nie.

    stock = {("sklep", 1): 10}
stock[("sklep", 1)] += 5
unique = set([3, 1, 3, 2, 1])
print(stock, len(unique))
    • {('sklep', 1): 15} 3Tak. Ta sama krotka trafia w ten sam klucz, a zbiór zostawia trzy różne wartości.
    • {('sklep', 1): 10, ('sklep', 1): 5} 5Słownik ma jeden wpis na klucz, a zbiór nie trzyma powtórzeń.
    • Błąd: krotka nie może być kluczemMoże, bo jest niezmienna. Kluczem nie może być lista.

    Comprehensions

    Pętla, która buduje nową kolekcję z elementów starej, ma w Pythonie krótszy zapis. Czyta się go jak zdanie: "weź to dla każdego elementu, który spełnia warunek".

    known = []
for value in values:
    if value is not None:
        known.append(value)

known = [value for value in values if value is not None]      # to samo
by_name = {name: sum(v) for name, v in series.items()}        # słownik
codes = {name[0] for name in series}                          # zbiór

    Comprehension to wyrażenie, więc tworzy nową kolekcję i niczego nie zmienia po drodze. To pasuje do reguły "funkcja zwraca nowy obiekt". Kiedy logika ma więcej niż jeden warunek i jedno przekształcenie, zwykła pętla jest czytelniejsza. Nie ma nagrody za zmieszczenie wszystkiego w jednej linii.

    values = [0, 2, None, 0, 5]
print([v * 10 for v in values if v])
    • [0, 20, 0, 50]Warunek if v odrzuca wszystko, co jest fałszywe w kontekście logicznym, a 0 jest fałszywe tak samo jak None.
    • [20, 50]Tak. if v odrzuca None, ale też zera. Jeśli chodzi Ci tylko o braki, pisz if v is not None.
    • Błąd: nie można mnożyć NoneNone nie dochodzi do mnożenia, bo odpada w warunku.
    Pułapka

    Zero sprzedaży to informacja, a brak pomiaru to jej brak. W danych o popycie if v po cichu wyrzuca zera razem z brakami. Pisz warunek, który mówi dokładnie, o co Ci chodzi.

    Iteracja i generatory

    Pętla for działa na wszystkim, co da się iterować: listach, słownikach (po kluczach), plikach (po liniach), zakresach. Pod spodem Python prosi obiekt o kolejne elementy, aż ten powie, że ich nie ma.

    Generator to funkcja, która zamiast return ma yield. Nie liczy wszystkiego od razu. Oddaje jeden element, zatrzymuje się i czeka, aż pętla poprosi o następny. Dzięki temu plik z milionem linii możesz przetwarzać linia po linii, trzymając w pamięci jedną.

    def data_lines(lines):
    for line in lines:
        if not line.startswith("#"):
            yield line.strip()
    def numbers():
    print("start")
    yield 1
    print("po jedynce")
    yield 2

gen = numbers()
print("utworzony")
print(next(gen))
    • start, utworzony, 1Wywołanie numbers() nie uruchamia ciała funkcji. Tworzy tylko generator.
    • utworzony, start, 1Tak. Ciało rusza dopiero przy pierwszym next i zatrzymuje się na pierwszym yield. "po jedynce" jeszcze się nie wypisało.
    • utworzony, start, 1, po jedynce, 2next prosi o jeden element, nie o wszystkie.

    Generator można przejść tylko raz. Druga pętla po tym samym generatorze nie zobaczy żadnego elementu. Jeśli potrzebujesz danych dwa razy, zapisz je do listy: list(gen).

    Pliki i with

    Otwarty plik trzeba zamknąć, także wtedy, gdy w trakcie czytania poleci błąd. Robi to za Ciebie with: blok kończy się zamknięciem pliku, bez względu na to, jak się kończy.

    from pathlib import Path

path = Path("data/raw/car_parts/car_parts_dataset_with_missing_values.tsf")
with path.open(encoding="utf-8") as handle:
    for line in handle:          # plik jest iterowalny: linia po linii
        ...
# tutaj plik jest już zamknięty

    Dwa nawyki na cały kurs:

    • Ścieżki składasz z pathlib.Path operatorem /, nie sklejasz napisów. Path("data") / "raw" / "plik.tsf" działa tak samo w Linuksie i w Windows.
    • Zawsze podajesz encoding="utf-8". Domyślne kodowanie zależy od systemu, a polskie znaki i symbole walut rozjeżdżają się pierwsze.

    with działa z każdym obiektem, który umie się "otworzyć" i "zamknąć": plikiem, połączeniem z bazą, blokadą. Takie obiekty nazywa się context managerami. Własny napiszesz w module 02.

    Wyjątki

    Wyjątek to sygnał "nie mogę zrobić tego, o co prosisz". Ma typ i komunikat. Typ mówi, co za problem (ValueError: zła wartość, KeyError: brak klucza, FileNotFoundError: brak pliku), komunikat mówi szczegóły.

    def parse_value(text):
    if text == "?":
        return None
    try:
        return float(text)
    except ValueError as error:
        raise ValueError(f"Not a number: {text!r}") from error

    Trzy zasady:

    • Łap konkretny typ. except ValueError, nie gołe except. Gołe łapie wszystko, także literówkę w nazwie zmiennej i Ctrl+C.
    • Nie połykaj. except: pass zamienia błąd w cichy zły wynik. Jeśli łapiesz, to po to, żeby coś zrobić: dodać kontekst i rzucić dalej, albo świadomie obsłużyć.
    • Komunikat z wartością. "Not a number: 'abc'" od razu mówi, co poszło nie tak. "Invalid input" nie mówi nic.
    def safe_total(values):
    total = 0
    for v in values:
        try:
            total += float(v)
        except:
            pass
    return total

print(safe_total(["1", "2", "?", "3O"]))
    • 6.0"3O" to trzy i litera O, nie zero. float go nie odczyta.
    • 3.0Tak. "?" i "3O" po cichu wypadły. Funkcja zwraca liczbę, która wygląda wiarygodnie, a jest zła. Tak wygląda cichy błąd.
    • Błąd: ValueErrorByłby, gdyby nie except: pass. I to byłoby lepsze zakończenie.
    Reguła

    except łapie konkretny typ. Bez gołego except i bez except: pass.
